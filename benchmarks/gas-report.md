# SPHINCS- C13 Gas Report — Phase 1 & 1b

Date: 2026-08-24
Environment: Foundry 1.7.1 (solc 0.8.28, optimizer 200 runs, legacy pipeline — NOT via-ir), Anvil defaults.

## What was measured

`SphincsMinusVerifier.verify(bytes32 pkSeed, bytes32 pkRoot, bytes32 message, bytes sig)`
on three static vectors generated by the reference Rust signer
(`nconsigny/SPHINCs-`, `signer-c13`). Identical inputs were run against the
reference Yul-optimized contract (`SPHINCs-C13Asm.sol`) for comparison.

## Results

| Verifier | Style | Gas (verify only) | Notes |
|---|---|---|---|
| `SPHINCs-C13Asm.sol` (reference) | single inline-assembly block | **100,251** | deterministic across all 3 vectors |
| `SphincsMinusVerifier.verify` (ours, Phase 1b) | optimized assembly hot path | **105,707** | +5.4% vs reference, all 3 vectors within 1 gas of each other |
| `SphincsMinusVerifier.verifyReadable` (ours, Phase 1 v0) | readable Solidity | **~600K** | kept as differential-testing oracle |

### Reconciling with the published number

The June 2026 ethresear.ch post reports **~127,000 gas** for C13. Our reference
measurement excludes transaction-level calldata cost: a 3,704-byte signature
plus ABI overhead (~3.7 KB × 16 gas/nonzero-byte ≈ 59K) brings the end-to-end
figure into the published range under EIP-7623-style floor pricing. The paper's
numbers check out, independently reproduced.

### Measurement pitfall worth documenting

Our first benchmark read the signature from **storage inside the timed region**,
adding ~250K gas of cold SLOADs and inflating results to ~360K. Inputs must be
decoded to memory before `gasleft()`. The numbers above are pure verification.

## Phase 1b notes

- The optimized path is a single inline-assembly block: fixed scratch slots,
  no allocation, branchless Merkle swaps, calldata-direct loads.
- Compiling with `via_ir = true` adds ~260K gas around the assembly block;
  the project pins `via_ir = false`. (The readable oracle needed restructuring
  to compile without IR — helper extraction plus a memory struct.)
- Correctness gate for the optimization is differential fuzzing: the optimized
  `verify` and readable `verifyReadable` must agree bit-for-bit on acceptance
  across mutated signatures (256+ random mutation cases per run).

## Reproducing

```shell
forge test --match-contract SphincsVerifierTest -vv   # correctness + benchmark
forge test --match-contract DifferentialTest -vv      # impl-vs-impl agreement
```

Vectors in `test/vectors/c13.json` were generated with the reference Rust
signer (`signer-c13 c13 <msg-hex>`) and are committed for reproducibility.

# Phase 3 — Portability Validation

Date: 2026-08-24
Method: `script/BenchmarkChains.s.sol` forked against each chain's live state
via public RPC (publicnode), deploying identical verifier bytecode and measuring
`verify()` on committed vector 0. Two runs per chain for determinism.

## Execution gas per chain

| Chain | Chain ID | Block | verify() gas |
|---|---|---|---|
| Ethereum Sepolia | 11155111 | 11,561,547 | **98,118** |
| Arbitrum Sepolia | 421614 | 11,561,548 | **98,118** |
| Base Sepolia | 84532 | 45,930,912 | **98,118** |
| OP Sepolia | 11155420 | 47,913,796 | **98,118** |
| Polygon Amoy | 80022* | — | **98,118** |

*Amoy chain id is 80002.

Identical to the last digit across all five chains — EVM execution pricing for
the opcodes SPHINCS- uses (KECCAK256, PUSH, MLOAD/MSTORE, flow control) does
not vary between these L1/L2 environments. Local Anvil measured 105,707 due to
dev-tooling gas-schedule differences, not chain differences.

## The real cross-chain cost driver: data availability

Execution gas is only part of the story. A C13 signature is 3,704 bytes of
calldata:

- **Ethereum / L1 rollups**: calldata costs ~16 gas/nonzero-byte at execution
  layer, plus (on L2s) an L1 data-availability fee that scales with blob and
  basefee markets. Expect the *dominant* UserOp cost on Arbitrum/Base/OP to be
  L1 data posting of the signature, not the 98K execution gas.
- **Validiums / alt-DA**: different tradeoff entirely; out of scope here.

Phase 3 follow-up (deferred with live-bundler testing): measure actual
end-to-end UserOp receipts per chain once funded keys are available.

## Reproducing

forge script script/BenchmarkChains.s.sol --fork-url <RPC> -vvv
